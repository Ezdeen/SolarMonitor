# مكتبة ملفات التعريف (profiles)

كل ملف `.json` هنا يصف خريطة سجلات Modbus لماركة/موديل واحد. الوكيل يجرّب SunSpec أولاً، ثم هذه الملفات بالترتيب (حسب `priority`).

## إضافة ماركة جديدة
1. انسخ `_template.json` باسم `brand-model.json` وعبّئه من وثيقة Modbus Register Map للشركة.
2. شغّل: `node --env-file=.env agent.mjs --dry` وتأكد أن الرقم التسلسلي والإنتاج يطابقان تطبيق الشركة.
3. الملف يبقى `"status": "unverified"` (لا يرسل فعلياً) حتى تطابق الأرقام، ثم غيّره إلى `verified`.
   للتجربة فقط: `ALLOW_UNVERIFIED_PROFILES=1` في `.env`.

## الحقول
- `function`: 3 (Holding) أو 4 (Input) — `unit`: رقم الوحدة — `addressOffset`: إزاحة العنوان (غالباً 0 أو -1).
- `serial`: `address` و`words` و`pattern` (تعبير نمطي يجب أن يطابقه السيريال، وهو ما يمنع التعرف الخاطئ).
- `daily` (اختياري): عداد يومي. إن حُذف يُشتق الإنتاج من الفرق في `total`.
- `total`: العداد الإجمالي. `words` = 1 أو 2، و`wordOrder` = `high-low` أو `low-high`، والناتج بعد `scale` يجب أن يكون kWh.
- `ratedW` (اختياري لكن مفيد): القدرة الاسمية بالواط، لرفض القفزات غير المعقولة.

ملفات تبدأ بـ `_` تُتجاهل. ملف غير صالح يُبلَّغ عنه في السجل ولا يوقف الوكيل.
